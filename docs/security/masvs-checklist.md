# MASVS v2 checklist with evidence (M4-06)

Profile: MAS-L1, plus the MAS-R resilience hook (NFR-12). This checklist is copied from [`04_SECURITY_DESIGN.md` §5](../04_SECURITY_DESIGN.md) and filled in with the evidence as built at M4, 7 November 2026. Each row links the code, test or document that proves it, and says what is still manual.

**Status key:**
- ✅ automated evidence in CI.
- 🔶 automated in part; the rest needs a real-device or manual check, listed in the threat model's open items ([threat-model.md §7](threat-model.md)).
- ➖ not applicable, with the reason.
- 🔗 integrator's responsibility; the documentation tells them how.

Paths are relative to the repository root.

## STORAGE

| Control | Status | How | Evidence |
|---|---|---|---|
| MASVS-STORAGE-1: sensitive data stored securely | ✅ / 🔶 | Seeds live only in the platform vault, encrypted at rest. Android: AES-256-GCM under a non-exportable Keystore key, files in `noBackupFilesDir`. iOS: Keychain `ThisDeviceOnly`. Web: AES-256-GCM under a non-extractable WebCrypto key. The account index is encrypted the same way. | `packages/flutter_mfa/android/src/test/kotlin/com/breaktroughf1/flutter_mfa/FileVaultTest.kt` (only ciphertext on disk, tampering, relabelling); `…/androidTest/…/KeystoreVaultInstrumentedTest.kt` (real Keystore, `noBackupFilesDir`, non-exportable key); `packages/flutter_mfa/example/ios/RunnerTests/RunnerTests.swift` (`ThisDeviceOnly`, not synchronizable); `packages/flutter_mfa/test/src/web/web_vault_test.dart`, `packages/flutter_mfa/test/web/flutter_mfa_web_test.dart` (non-extractable key, AAD swap); `packages/flutter_mfa/test/src/client/mfa_client_test.dart` (index holds no secret). 🔶 Manual: filesystem inspection on a device (dynamic-test guide, D1). |
| MASVS-STORAGE-2: prevent leakage of sensitive data | ✅ / 🔶 | No-backup location and `ThisDeviceOnly`. Logs carry event names and account ids only. `toString` is redacted. Native code never logs, and its errors carry a code only. The clipboard is sensitive and expires. Backups are always encrypted. | `packages/flutter_mfa/test/src/logging/log_leak_test.dart` (whole journey: no secret, code, passphrase or URI in any log); `packages/flutter_mfa_core/test/src/otp/otp_secret_test.dart`, `…/backup/backup_codec_test.dart`, `…/client/relying_party_enrollment_test.dart` (redacted `toString`); `tool/forbidden_apis.sh` (no `print`/`Log.*`/`NSLog` in libraries or native vault code); `packages/flutter_mfa/test/src/client/code_stream_test.dart` (sensitive copy and expiry). 🔶 Manual: OS backup extraction, clipboard on Android ≤ 12 (D2, D5). |

## CRYPTO

| Control | Status | How | Evidence |
|---|---|---|---|
| MASVS-CRYPTO-1: strong, current cryptography | ✅ | HMAC-SHA1/256/512 per RFC 4226/6238. AES-256-GCM. PBKDF2-HMAC-SHA256 with 600 000 iterations. RSA-2048 OAEP only to wrap per-entry data keys (Android biometric entries). ECIES P-256 for iOS `hardwareBound`. No custom crypto. ECB, CBC, MD5 and `Random()` are banned by CI. | [`04_SECURITY_DESIGN.md` §6](../04_SECURITY_DESIGN.md); `packages/flutter_mfa_core/test/vectors/rfc4226_test.dart`, `rfc6238_test.dart`; `packages/flutter_mfa_core/test/src/backup/backup_kat_test.dart` (frozen backup, VM + dart2js + dart2wasm, every backend); `packages/flutter_mfa_core/tool/crosscheck_backup.py` (independent Python reproduction); `tool/forbidden_apis.sh`. |
| MASVS-CRYPTO-2: key management | ✅ / 🔶 | Keys are generated by the platform and never exported. Aliases are per purpose and per entry, with random ids. Biometric keys are invalidated on enrolment change. Software-only Android keys are refused. A fresh salt and nonce are used for each backup. | `…/androidTest/…/ProtectedKeysInstrumentedTest.kt` (RSA-OAEP opens with a real Keystore key; fails closed without biometrics); `…/test/…/FileVaultTest.kt` (key lifecycle on replace, delete and wipe; rollback); `packages/flutter_mfa/example/ios/RunnerTests/RunnerTests.swift` (Secure Enclave unavailable gives a clear error; key-name binding); `packages/flutter_mfa_core/test/src/backup/backup_codec_test.dart` (fresh salt and nonce). 🔶 Manual: invalidation after a new enrolment, StrongBox, Secure Enclave ([05 §5.1](../05_TEST_PLAN.md)). |

## AUTH

| Control | Status | How | Evidence |
|---|---|---|---|
| MASVS-AUTH-1: secure authentication protocols | 🔗 / ✅ | The library verifies codes with replay protection and a limiter that runs before any HMAC. The docs require verification on the server, a persisted `lastUsedStep` and a shared, atomic attempt store (ADR-0014). | `packages/flutter_mfa_core/test/src/verify/verifier_test.dart` (window, drift, replay, malformed input, limiter before HMAC); `packages/flutter_mfa_core/test/src/limit/attempt_limiter_test.dart` (back-off, lockout, no lost failures across processes); [`docs/cookbook/verify-on-a-dart-server.md`](../cookbook/verify-on-a-dart-server.md). |
| MASVS-AUTH-2: local authentication per platform best practice | ✅ / 🔶 | Biometrics are tied to a key operation: Android `BiometricPrompt` + `CryptoObject` (Class 3, per use), iOS `SecAccessControl(.biometryCurrentSet)` and a Secure Enclave key. There is no boolean API (FR-VLT-06 AC4). Saving never prompts; every read does. | `…/test/…/FileVaultTest.kt` (no prompt on write, a prompt on every read, cancel and invalidation mapping); `…/test/…/BiometricErrorTest.kt`; `packages/flutter_mfa/example/ios/RunnerTests/RunnerTests.swift` (error mapping); ADR-0004 and its implementation notes. 🔶 Manual: the prompt itself, lockout, a Frida bypass attempt (D3). |
| MASVS-AUTH-3: extra authentication for sensitive operations | ✅ | `biometric` and `hardwareBound` levels per account. Export needs a passphrase that meets the policy (checked before any secret is read). Import needs the passphrase and is all or nothing. | `packages/flutter_mfa/test/src/client/backup_test.dart`; `packages/flutter_mfa_core/test/src/backup/passphrase_policy_test.dart`; `packages/flutter_mfa/example/integration_test/app_test.dart` (backup and restore on every CI device). |
