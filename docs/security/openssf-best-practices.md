# OpenSSF Best Practices: answer sheet

Answers for the [OpenSSF Best Practices badge](https://www.bestpractices.dev) ("passing" level), with the evidence for each criterion. Sign in at bestpractices.dev with the GitHub account that administers the repository, add the project `https://github.com/Breaktroughf1/flutter_mfa`, then paste the status and justification for each criterion below. Links are relative to the repository root on `main`.

Status values: **Met**, **N/A** (with the reason), or **Unmet**. Every MUST criterion below is Met or N/A. After the badge is granted, add its README badge (the site shows the Markdown) and replace `PROJECT_ID` in [the README](../../README.md).

Last checked: 24 November 2026 (0.3.0 release preparation).

## Security

| Criterion | Status | Justification |
|---|---|---|
| know_secure_design | Met | [docs/04_SECURITY_DESIGN.md](../04_SECURITY_DESIGN.md), [threat model](threat-model.md), ADRs. |
| know_common_errors | Met | [MASVS checklist](masvs-checklist.md) with evidence; OWASP MASTG-based [dynamic test guide](dynamic-test-guide.md). |
| crypto_published | Met | HOTP/TOTP (RFC 4226/6238, HMAC-SHA1/256/512), PBKDF2-HMAC-SHA256, AES-256-GCM, RSA-OAEP key wrap (Android), ECIES P-256 (iOS Secure Enclave). |
| crypto_call | Met | No custom cryptography: `package:crypto` (HMAC), `package:cryptography` and WebCrypto (PBKDF2, AES-GCM), Android Keystore, iOS CryptoKit/Security. |
| crypto_floss | Met | `crypto` and `cryptography` are BSD/Apache-2.0; platform APIs are used where FLOSS is not available. |
| crypto_keylength | Met | AES-256, RSA-2048, P-256, PBKDF2 with 600 000 iterations, OTP secrets of at least 160 bits (generated: 160/256/512 bits by algorithm). |
| crypto_working | Met | No broken algorithms. HMAC-SHA1 is used only inside HOTP/TOTP as the RFCs and authenticator apps require; HMAC-SHA1 is not affected by SHA-1 collision attacks. |
| crypto_weaknesses | Met | HMAC-SHA-256 and HMAC-SHA-512 are supported; HMAC-SHA1 is the default because RFC 6238 and authenticator apps expect it (crypto inventory in docs/04_SECURITY_DESIGN.md §6). |
| crypto_pfs | N/A | The packages make no network connections. |
| crypto_password_storage | N/A | The packages store no passwords. The backup passphrase is never stored; it derives the backup key with PBKDF2-HMAC-SHA256 (600 000 iterations, random salt). |
| crypto_random | Met | OTP secrets and account ids come from `Random.secure()`; keys and nonces come from the platform CSPRNGs (Android Keystore/JCA, iOS `SecRandomCopyBytes` and CryptoKit, web `crypto.getRandomValues`). `tool/forbidden_apis.sh` fails CI on a seeded `Random` in library code. |
| delivery_mitm | Met | Distributed through pub.dev (HTTPS) and GitHub (HTTPS); releases are published from GitHub Actions with OIDC. |
| delivery_unsigned | Met | No downloads of hashes over HTTP. |

| vulnerabilities_critical_fixed | Met | As above. |

## Toward silver

Not needed for "passing". These are the main gaps for the silver level:
- **Two-person review of changes.** Two maintainers hold admin access ([GOVERNANCE.md](../../GOVERNANCE.md)), so access continuity is covered; silver also expects changes to be reviewed by someone other than their author.
- **Signed releases**: sign release tags (`git tag -s`), as `docs/07_RELEASE_RUNBOOK.md` §A.5 already plans.
- **Roadmap**: publish one (for example in GitHub Discussions or the docs site).

## OpenSSF Scorecard

[.github/workflows/scorecard.yml](../../.github/workflows/scorecard.yml) runs weekly and on every push to `main`, publishes results to `https://scorecard.dev/viewer/?uri=github.com/Breaktroughf1/flutter_mfa`, and feeds the README badge. Expected weak spots and what fixes them:

| Check | Why it may score low | Fix (maintainer) |
|---|---|---|
| Code-Review | Most merged changes had no second approval. | Require one approving review in branch protection, with a second maintainer. |
| Branch-Protection | Depends on repository settings. | Protect `main`: pull requests required, status checks `ci-full` jobs and `CI` required, no force pushes, admins included. |
| Signed-Releases | Release tags and GitHub releases are not signed. | Signed tags; GitHub releases with provenance. |
| Contributors | One organisation. | Grows with outside contributors. |
| Fuzzing | Scorecard recognises OSS-Fuzz and a few language fuzzers, not Dart property tests. | None required; the property tests remain the evidence for bestpractices.dev. |
| SAST | Scorecard looks for CodeQL or similar; CodeQL has no Dart support. | Optional: CodeQL for the Kotlin and Swift sources. |

Checks already covered by the repository: Security-Policy, License, Dependency-Update-Tool (Dependabot), Pinned-Dependencies (all actions and shared workflows pinned by SHA), Token-Permissions (read-only by default in every workflow), Dangerous-Workflow, CI-Tests, Packaging (pub.dev publishing from GitHub Actions), Vulnerabilities, Maintained.
