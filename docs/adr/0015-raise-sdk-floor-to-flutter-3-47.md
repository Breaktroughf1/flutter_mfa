# ADR-0015: Raise the SDK floor to Dart 3.13 / Flutter 3.47

- Status: Accepted (24 November 2026, maintainer: "do what's optimal; every package at 160/160")
- Supersedes the floor in CLAUDE.md rule 9 and PRD NFR-07 (Dart 3.9 / Flutter 3.35, set at M0-05)

## Context
pub.dev scores every package with the latest stable SDK. On Flutter 3.50, `flutter_mfa_ui` 0.2.0 dropped to 140/160 for two reasons:

1. **Up-to-date dependencies (−10).** `qr: ^3.0.2` excludes `qr` 4. `qr` 4 changed its API (`QrCode.fromData` is gone; error-correction levels are an enum) and requires Dart 3.13, so no constraint can cover both majors with one source.
2. **Static analysis (−10).** Since Flutter 3.47, `package:flutter/material.dart` and `cupertino.dart` are deprecated in favour of the `material_ui` and `cupertino_ui` packages. The two theme adapters import them, and the localisations generated by `gen-l10n` use the deprecated `flutter_localizations` Material and Cupertino delegates. `material_ui` and `cupertino_ui` need Flutter 3.47 / Dart 3.13 as well.

`flutter_mfa_qr` depends on `flutter_mfa_ui`, and the repository is one pub workspace, so a floor raised in one package applies to all of them.

## Decision
- Every package requires **Dart `>=3.13.0 <4.0.0` and Flutter `>=3.47.0`**. Android minSdk 24, iOS 15 and secure-context web are unchanged.
- All five packages are released as **0.3.0**. Sibling constraints are `>=0.2.0 <0.4.0`: the APIs they use from each other did not change between 0.2 and 0.3, and the range lets pana (which resolves from pub.dev) score each package before its siblings' 0.3.0 is published.
- `flutter_mfa_ui`:
  - The adapters import `package:material_ui` and `package:cupertino_ui` (new dependencies: BSD-3-Clause, Flutter team; lower bounds `^1.4.0` and `^1.1.1`, the first releases that require Flutter 3.47).
  - `qr: ^4.0.1`.
  - `tool/check_no_material_in_ui.sh` now bans `material_ui` and `cupertino_ui` outside the two adapter files too.
- Generated localisations: `l10n.yaml` adds the header `// ignore_for_file: deprecated_member_use`, because Flutter's `gen-l10n` (still in 3.50) emits the deprecated delegates and offers no option to leave them out. The README recommends registering `MfaLocalizations.delegate` next to the design system's own delegates. Remove the header once `gen-l10n` stops emitting them.
- CI tests the floor with the newest 3.47 patch (`FLUTTER_MIN_VERSION`) and the rest with the latest stable that pub.dev scores with (`FLUTTER_VERSION`).

## Consequences
+ Every package can score 160/160 on the current stable SDK, and the adapters follow Flutter's own migration path.
+ One floor for the workspace, tested in CI.
− Apps on Flutter 3.35–3.44 stay on 0.2.x.
− Apps still importing `package:flutter/material.dart` can't use the 0.3.0 adapters (`ThemeData` from the SDK library and from `material_ui` are different types). They can stay on 0.2.x, migrate, or build an `MfaThemeData` directly. Recorded as breaking in the 0.3.0 CHANGELOG.
